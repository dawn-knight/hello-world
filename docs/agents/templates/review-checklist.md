# Review Checklist (Game Dev)

Use this for peer reviews of code, assets, and docs.

## Scope & intent

- [ ] The change matches the task brief and acceptance criteria.
- [ ] Non-goals were respected (no scope creep).

## Player experience

- [ ] Controls feel consistent and readable.
- [ ] Feedback is clear (audio/visual/haptics if applicable).
- [ ] Failure states are fair and understandable.

## Technical quality

- [ ] No obvious performance regressions; budgets considered.
- [ ] Code is readable and appropriately modular.
- [ ] Logging/telemetry (if any) is actionable and not noisy.
- [ ] Data formats and naming conventions are consistent.

## Content quality (art/audio)

- [ ] Asset naming and folder placement follow conventions.
- [ ] Import settings are correct (compression, scale, pivots, etc.).
- [ ] Sizes are within budget; duplicates avoided.

## QA & docs

- [ ] Test plan is included and makes sense.
- [ ] Repro steps for fixed bugs are clear.
- [ ] Docs/controls/help text updated if behavior changed.

## Handoff

- [ ] `templates/handoff.md` completed with next actions.
